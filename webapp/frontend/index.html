What the frameworks mean

MBTI — Myers-Briggs Type Indicator

A four-letter type describing how you prefer to focus energy, take in information, make decisions, and organize your life. Four axes: Introvert / Extravert, iNtuitive / Sensing, Thinking / Feeling, Judging / Perceiving. 16 combinations, e.g. INTJ.

Holland Codes — RIASEC

Six interest types: Realistic (builders/doers), Investigative (thinkers/analysts), Artistic (creators), Social (helpers/teachers), Enterprising (persuaders/leaders), Conventional (organizers). Your top three form a code like RIE, which maps to occupations on O*NET.

Big Five — OCEAN

Five personality traits, each on a spectrum (Low → High): Openness to experience, Conscientiousness, Extraversion, Agreeableness, Neuroticism (emotional stability). Remember it as OCEAN.

Under the hood

How Anitalmid works

Anitalmid is a rules engine + keyword scorer, not a language model. It counts words against curated dictionaries and applies fixed formulas. There's no neural network, no token stream, no generation, no API call to a model. The whole thing is deterministic local computation.

What actually happens under the hood

Text in

A PDF is parsed by pymupdf into plain text (or you paste text / pick signals directly). That's it for input.

Signal detection (signal_detection.py)

The "magic" is lexicon counting:

  • MBTI: each of the 4 dichotomies (I/E, N/S, T/F, J/P) has a curated list of keyword stems. It regex-counts how many hits each pole gets, and the higher-count pole wins. You typed more "collaborate, team, together" → E; more "focused, quiet, reflect" → I.
  • Holland (RIASEC): same idea: six interest buckets, count keyword hits, take the top three as your code.
  • Big Five (OCEAN): five traits, each with its own lexicon. Because "Openness" has ~30 keyword stems and "Stability" ~16, it coverage-normalizes each trait (divides by lexicon size) so a short resume doesn't collapse everything to "Low."
Scoring (resume_matcher.py + scoring.py)

Your inferred signals are compared against a catalog of 150 role profiles (roles.py), each a fixed dataclass with its own mbti_type, holland_code, and keyword lists. The formula is explicit arithmetic:

Framework compatibility = MBTI match × 50% + Holland match × 50%

That's blended with resume-keyword overlap (60/40). Every role gets a number, and they're sorted. No model, just math.

Validation + map

The ranking is sanity-checked against the OSKG graph, then the career map is drawn as a fixed graph of nodes (profile → signals → roles) and edges. Deterministic all the way down.

Even the job-posting matcher is LLM-free

It scrapes the posting's JobPosting metadata, runs the same signal detector over the description to infer the job's MBTI/Holland/Big Five, then compares against yours with keyword overlap + signal comparison.

Why it doesn't need an LLM

The task is structured mapping, not open-ended generation: text → known categories → ranked roles. That's classic deterministic NLP (frequency/keyword matching), the kind of thing that predates LLMs by decades. The "detailed explanations" you see are templates filled with the counted data (e.g. "You're missing 26 keyword(s) the posting emphasizes"), not generated prose.

The trade-off (honest)

What an LLM would do better

Understand synonyms, context, negation ("I'm not a people person"), and nuance. Lexicons are brittle to wording.

What the deterministic approach buys you

Zero cost per analysis, runs offline, instant, fully auditable (you can trace exactly why a role scored X, no black box), no hallucination, and your resume never gets shipped to a third-party model. A real privacy win for something as sensitive as a career history.

So the short answer to "how does it not use an LLM?" Because it never generates anything. It only counts and sorts, with formulas you can open up and read. 🏴‍☠️
